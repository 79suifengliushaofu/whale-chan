# 鲸鱼娘 · 发布方案

> 这份文档回答三个问题：**她到底怎么装到用户机器上？** 是 DSH 插件库、GitHub，还是
> 编译器（IDE）的插件商店？在编译器的插件商店里发布**需不需要让用户配 API Key**？

---

## 0. 先给结论

| 渠道 | 存在吗 | 适合谁 | 要不要 API Key |
| --- | --- | --- | --- |
| **DSH 插件库「绑定安装」** | ⚠️ **DSH 没有官方插件市场**。官方只有**包管理器**（`dsh plugin --profile <p> add <spec>` / `plugin_manager install_bundle`）。生态里唯一的「市场」是社区项目 QT7-C23/DSH-Marketplace | DSH Web 端的桌宠/挂件类插件 | ❌ 不需要（可复用 DSH 已登录账号） |
| **GitHub 仓库** | ✅ 随时可发，也是另外两条路的前置条件 | 所有人；`dsh plugin add github:…` 能直装 | ❌ 不需要 |
| **编译器（IDE）插件商店** | ✅ VS Code Marketplace / Open VSX 都是现成的；JetBrains Marketplace 需要另写 Kotlin 插件 | 要「装在 VS Code / PyCharm 里、开箱即用」的人 | ❌ **不需要** |

**关于 API Key 的正面回答：不需要。**
鲸鱼娘终端是一个**跑在本机的 CLI**，它调用的是用户机器上**已经登录过**的
`dsh`（DeepSeek Harness）——凭据在 `~/.dsh/.credentials.yaml` 里，由 DSH 自己管。
VS Code 扩展本身只是「用 `node` 把 CLI 拉起来、塞进集成终端」，完全不碰任何 Key。
扩展里唯一的设置项是 `whaleChan.cliPath / nodePath / profile / permission`，没有一个跟密钥有关。

> 生态里两条路线都有先例：MeteorNOX 的余额挂件会回落用 DSH 已登录的 `deepseekAccount`
> 服务（免 Key），而 comreade-123 的 Electron 桌面版要求用户**手填 `sk-` Key**。
> 我们选前者，因为它对用户更省事，也不需要为密钥做本地加密存储。

**推荐的发布顺序：**

```
① GitHub 开源（MIT 代码 + 素材声明）  →  ② VS Code Marketplace / Open VSX 上架  →  ③（可选）社区 DSH Marketplace
```

## 1. 路线 A：GitHub（第一步，必做）

### 1.1 仓库该长什么样

```
whale-chan/
├── LICENSE                 # MIT（代码）
├── ASSETS-NOTICE.md        # ⚠️ 美术素材不属于 MIT，见 1.3
├── README.md               # 现成的，含截图、接法对照表、权限说明
├── package.json            # name: whale-chan-terminal, bin: whalechan
├── bin/whalechan.mjs
├── src/*.mjs               # 8 个文件，**零运行时依赖**
├── assets/whale-q.png|json # 从 DSniang1.png 烘焙出来的六张表情
├── ide/
│   ├── vscode/             # VS Code 扩展 + vendor/ 自包含运行时
│   ├── jetbrains/          # External Tools XML + 接法说明
│   └── bin/                # whalechan.cmd / whalechan 启动器
└── tools/                  # bake-q.mjs 等构建脚本（**发布包里可以不放**）
```

### 1.2 发布到 npm（让 `npx whalechan` 可用）

照搬 `dsh-whale-widget` 的做法——它自 0.2.1 起全部由
**GitHub Actions OIDC Trusted Publishing** 自动发布，并且带 provenance 签名，
不需要在仓库里存任何长期 token：

```yaml
# .github/workflows/publish.yml
name: publish
on:
  push:
    tags: ['v*']
jobs:
  npm:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write        # OIDC，关键
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, registry-url: 'https://registry.npmjs.org' }
      - run: npm publish --provenance --access public
```

配好 npm 网站上的 Trusted Publisher 之后，`npm publish` 靠 OIDC 自动认身份。

### 1.3 ⚠️ 素材版权：必须写清楚，否则不要发布

鲸鱼娘本体 `assets/DSniang1.png` 来自
[MeteorNOX/DeepSeek-Balance-Whale-Widget](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget)。
该项目**代码是 MIT，但 `assets/` 目录明确不在 MIT 覆盖范围内**，按原样分发、不授予再许可；
两张角色图都是来源不可追溯的 AI 生成图。

所以我们的做法是：

- **代码**（`bin/ src/ ide/ tools/`）→ MIT，可以随便用。
- **美术**（`assets/whale-q.png`）→ 单列 `ASSETS-NOTICE.md`：
  - 写明来自 MeteorNOX 的 `DSniang1.png`，附仓库链接与获取日期；
  - 声明**不随本项目再次授权**，使用者需自行遵守上游的署名/使用要求；
  - 提供**不依赖该素材的重建路径**：`node tools/bake-q.mjs` 会从本机
    `dsh-whale-widget/assets/DSniang1.png` 重新烘焙，任何人可以换成自己的立绘
    （改 `tools/bake-q.mjs` 顶部的 `SOURCE` 与 `CROP` 即可）。
- 仓库描述里注明「角色立绘版权归原作者，本项目仅做终端化」。

> 如果做不到上面这些，就**只发代码、不发素材**，让用户自己在本地跑烘焙脚本。

### 1.4 DSH 用户可以直接从 GitHub 安装（如果将来做 Web 桌宠版）

```powershell
dsh plugin --profile web add github:你的用户名/whale-chan
# 或者用 agent 工具
plugin_manager { action: "install_bundle", target: "github:你的用户名/whale-chan" }
```

前提是包里声明了 DSH 的集成契约：

```json
{ "dsh": { "bundle": { "patch": "./cordis.patch.yml" } } }
```
```yaml
# cordis.patch.yml
- insert:
    - id: whale-chan-pet
      name: whale-chan
```

`dsh plugin add` 会把包装进 profile，pnpm 成功后把包名写进 `dsh.profile.bundles`，
返回 `application: applied`（HMR 立即生效）或 `restart-required`。

## 2. 路线 B：VS Code Marketplace / Open VSX（编译器插件商店）

### 2.1 先解决一个必踩的坑：Workspace Trust

我们的扩展**会 spawn 本机进程**，属于 VS Code 眼里的高风险行为。
`package.json` 里**不声明** `capabilities.untrustedWorkspaces` 就等于「受限模式下禁用」，
用户会遇到「扩展被禁用且不知道为什么」。必须显式声明：

```json
{
  "capabilities": {
    "untrustedWorkspaces": { "supported": false },
    "virtualWorkspaces": { "supported": false }
  }
}
```

官方文档还专门点名「工作区可改的设置值被当作命令行参数传给外部 CLI」是攻击面——
所以 `whaleChan.cliPath`、`whaleChan.nodePath` 这类设置**应当列入
`capabilities.untrustedWorkspaces.restrictedConfigurations`**，或者干脆只在受信任工作区生效。

### 2.2 打包与上架

```powershell
npm i -g @vscode/vsce
vsce package                      # 生成 whale-chan-terminal-1.0.0.vsix
vsce publish                      # 上架 VS Code Marketplace
```

发布前要做的：

1. **建 publisher 账号**（ID 创建后**不可修改**，想清楚再建）。
2. **PAT 权限**要 `Marketplace: Manage`。
   ⚠️ **2026-12-01 起 Azure DevOps 全局 PAT 退役**，新流程走
   **Entra ID + workload identity federation**：
   ```powershell
   vsce publish --azure-credential     # 需要 vsce >= 2.26.1
   ```
3. `icon` 不能用 SVG（用 PNG，建议 128×128）。
4. 扩展名一旦发布，**移除后也被永久保留**。

### 2.3 Open VSX（可选，但很值）

Open VSX 是 VSCodium / Gitpod / code-server 的默认市场，注册比 Marketplace 松：

```powershell
npx ovsx create-namespace <你的 publisher>   # 注意：不会自动给你独占发布权
npx ovsx publish whale-chan-terminal-1.0.0.vsix -p <token>
```

用 pnpm 打包时记得 `--no-dependencies` 或 `--follow-symlinks`，
也支持 GitHub OIDC 受信发布（`--trusted-publishing`）。

### 2.4 上架**不需要** API Key

Marketplace / Open VSX 的审核文档里**没有**任何一条要求扩展必须配置 API Key，
也没有针对「扩展 spawn 本机 CLI」的专项审核。真正要过的只有 2.1 的 Workspace Trust。

用户侧的实际体验：

```
1. 在 VS Code 里装 whale-chan-terminal
2. 打开集成终端 → 点终端右上角的 ⌄ → 选「鲸鱼娘」（或按 Ctrl+Alt+W）
3. 完事。不需要填任何 Key——用的是你本机 dsh 已经登录的身份。
```

### 2.5 PyCharm / JetBrains 怎么办

JetBrains 插件（Kotlin）是**另一个工程量级**的项目，不建议现在做。
现阶段已经能用的三种接法（见 `ide/jetbrains/README.md`）：

1. 在 PyCharm 的内置 Terminal 里直接敲 `whalechan`；
2. `Settings ▸ Tools ▸ Terminal ▸ Shell path` 指向 `whalechan.cmd`——
   以后每开一个终端就是鲸鱼娘；
3. External Tools（`ide/jetbrains/whale-chan-tools.xml`），
   选中文件右键 →「鲸鱼娘：问这个文件」。

如果之后要上 JetBrains Marketplace，就是把 3 包成一个 `AnAction` + `ToolWindow`，
再走 `./gradlew publishPlugin`——那是一条独立的路。

## 3. 路线 C：DSH 插件库（只有做 Web 桌宠版才需要）

DSH 侧**没有官方插件市场**。`@deepseek-ai/dsh-plugin-manager` 是包管理器，不是目录。
正规流程只有两条：

- **给用户**：`dsh plugin --profile <p> add <包名|github:…|link:…>`，
  或 agent 工具 `plugin_manager { action: "install_bundle", target: <spec 或绝对目录> }`。
  pnpm 成功后才把包选进 `dsh.profile.bundles`。
- **给发布者**：包里声明 `dsh.bundle.patch`，然后被装。要过的门：
  - 安装动作需要 danger-full-access 或逐次批准；
  - 已装的 Host 代码**不受工作区沙箱限制**（所以用户是拿安全换功能）；
  - pnpm 11 的构建脚本要在 `pendingBuilds` 里显式批准（`approvedBuilds`）；
  - DSH peer 版本不兼容会在 pnpm 之前就失败（`incompatible-version`），
    豁免要写 `compatibility.json` 且需要 `acceptRisk: true`；
  - 注册表顺序：`options.registry` → 配置里的 registry → 默认兜底 npmmirror；
  - **替换已装包之后必须重启 DSH 进程**才会加载新 JS。

### 社区市场 QT7-C23/DSH-Marketplace

生态里唯一的「市场」，**不是 npm 发布，是装 tgz**。提交流程：

1. 开 GitHub Issue 提案，写清：用途 / 原作者 / 来源版本 / 许可依据 / 使用方法 / 已知限制；
2. 维护者核对署名与授权；
3. 把条目写进 `catalog/resource-entries.json`；
4. `node catalog/build.mjs` + `npm run verify`；
5. PR **必须同时包含源文件与生成出来的 `catalog/index.json` / `registry.json`**
   （不许手改索引）；
6. 合并进 main 后，适配器按固定 commit 校验索引字节，客户端 6 小时自动同步。

要求：插件类型需要精确的 `packageRef: {name, version}`，安装时另查实际 manifest 与入口；
**没有 Star 数 / 仓库年龄门槛**；更新要重审；移除不需要指控侵权。

### 6.2 卡住的两件事（只有账号本人能解决）

**① GitHub 在这台机器上被 hosts 文件挡死了。**
`C:\Windows\System32\drivers\etc\hosts` 里有 28 行，把 `github.com`、`api.github.com`、
`raw.githubusercontent.com`、`avatars.githubusercontent.com` 等全指向 `127.0.0.1`。
当前进程**不是管理员**，改不了这个文件（`codeload.github.com` 没被挡，但 `git clone` / `git push`
走的是前者，所以照样失败）。要在这台机器上推代码，用**管理员**开一个 PowerShell 跑：

```powershell
$h = 'C:\Windows\System32\drivers\etc\hosts'
$bak = "$h.bak-$(Get-Date -Format yyyyMMdd-HHmmss)"
Copy-Item $h $bak
(Get-Content $h) | Where-Object { $_ -notmatch 'github' } | Set-Content $h -Encoding ASCII
Write-Host "原文件已备份到 $bak"
```

**② 三个渠道的令牌。** `vsce` / `ovsx` / `npm` 都不认识我，只认识你的账号：

| 渠道 | 你要做什么 | 产出 |
| --- | --- | --- |
| VS Code Marketplace | 去 <https://marketplace.visualstudio.com/manage> 用微软账号**创建 publisher**（ID 填 `whale-chan`，**创建后不能改名**）；再去 Azure DevOps 建 PAT，scope 勾 **Marketplace ▸ Manage** | `VSCE_PAT` |
| Open VSX | 用 GitHub 登录 <https://open-vsx.org>，然后 `npx ovsx create-namespace whale-chan` | `OVSX_PAT` |
| npm | <https://www.npmjs.com> → Access Tokens → 建一个 **Automation** token | `NPM_TOKEN` |

> ⚠️ Azure DevOps 的全局 PAT **2026-12-01 起退役**，之后要改用 Entra ID + workload identity
> federation（`vsce publish --azure-credential`，vsce ≥ 2.26.1）。我们装的是 4.0.0，现在用 PAT 就行。

### 6.3 拿到之后，两条命令发完

仓库地址**已经填好了**（`79suifengliushaofu/whale-chan`，见 `package.json` 的 `repository/homepage/bugs/qna`）。

### 6.4 代码怎么上 GitHub（本机发不了，必须换一台或先修 hosts）

**仓库根是 `C:\harness`，不是 `C:\harness\whale-chan`** —— 因为 `tools/`（构建脚本、
四个自检）和 `.github/workflows/` 都在仓库根，而 `whale-chan/` 是其中一个子目录。
`.gitignore` 已经把 `whale-chan-dist/`、`vendor/`、`tools/pub/`、`表情包/` 排掉了。

```powershell
cd C:\harness
git init
git add -A
git commit -m "whale-chan 1.8.0"
git remote add origin https://github.com/79suifengliushaofu/whale-chan.git
git branch -M main
git push -u origin main
git tag v1.8.0 && git push origin v1.8.0     # ← 触发 release.yml，自动发三条渠道
```

## 7. 实际结果（2026-09-27 收尾）

### 7.1 ✅ GitHub 已上架

- 仓库 <https://github.com/79suifengliushaofu/whale-chan>（public，默认分支 `main`）
- Release <https://github.com/79suifengliushaofu/whale-chan/releases/tag/v1.8.0>，附件
  `whale-chan-terminal-1.8.0.vsix`（2064.1 KB）
- CI run `36290131373` **全绿**：四个自检 → 打 vsix → 建 Release 全部成功

> 教训：hosts 里的 GitHub 封锁是 **Steam++（Watt Toolkit）**写的，而它有 Hosts 文件保护，
> 手动改会被它静默写回。必须在 Steam++ 自己那里删，或关掉保护再改。

### 7.2 ✅ npm 已发布

- <https://www.npmjs.com/package/whale-chan> —— `whale-chan@1.8.0`，MIT
- 装法：`npx whale-chan --help` 或 `npm i -g whale-chan`
- **登录态就是不能用**：`npm login --auth-type=web` 的设备流链接有时限，走神两分钟就超时，
> 然后退回问用户名、stdin 为空 → 退出 1。最后是靠**手动建令牌**过去的。

> **关键那一项：`Bypass 2FA` 必须是 `true`。**
> 判断办法不用猜，读 npm 自己的 API 就行：
> ```powershell
> curl.exe -sS -H "Authorization: Bearer npm_xxxx" https://registry.npmjs.org/-/npm/v1/tokens
> ```
> 返回里每个令牌都带 `"bypass_2fa": true|false`。
> 第一版令牌看着勾了那格，实际落库是 `false`，于是 `npm publish` 报：
> `403 ... Two-factor authentication or granular access token with bypass 2fa enabled is required`。
> 注意 `--otp=<码>` **救不了**这种情况（账号没开 2FA 时它给同一句 403），别再往那条路上试。

### 7.3 ✗ Microsoft Marketplace 已放弃

新建 Azure DevOps 组织**必须绑定一个有效的 Azure 订阅**（[官方答复](https://learn.microsoft.com/en-sg/answers/questions/5964239/existing-vs-code-marketplace-publisher-cannot-gene)），
没有订阅 → 建不出组织 → 开不出 PAT → 发不了。**Entra ID + `--azure-credential` 那条后路也一样要 Azure 资源**，不是免订阅方案。
影响不大：Cursor / Windsurf / Trae / VSCodium 这些国内常用 IDE **全部从 Open VSX 拉扩展**。

### 7.4 ⏳ 还差 Open VSX

按 §6.2 的表走就行，但顺序**不能反**：

1. <https://accounts.eclipse.org/user/register> 建 Eclipse 账号，
   **`GitHub Username` 一栏必须填 `79suifengliushaofu`**（和登录 open-vsx 用的必须是同一个 GitHub 账号）
2. 登录 <https://open-vsx.org> 用 **GitHub** 授权
3. <https://open-vsx.org/user-settings/profile> 点 **`Log in with Eclipse`** → 再点 **`Show Publisher Agreement`** → 读到底 → `Agree`
4. <https://open-vsx.org/user-settings/tokens> → `Generate New Token`

拿到之后：

```powershell
npx --yes ovsx create-namespace whale-chan -p <OVSX_PAT>
npx --yes ovsx publish whale-chan-dist/whale-chan-terminal-1.8.0.vsix -p <OVSX_PAT>
```

> 发布是**异步**的：刚发完显示 `Deactivated`，一般 5～10 秒后才可用。
> 另外「建了命名空间」不等于「认证发布者」，扩展页上会挂一个黄标，**不影响安装使用**。

### 7.5 最后一步：把 npm 交给 CI（可选，但建议）

npm 那条现在已经能自动发了，只差两件在网页上做的事：

1. <https://www.npmjs.com/package/whale-chan/access> → **Trusted Publisher** → 选 **GitHub Actions**，
   填组织 `79suifengliushaofu`、仓库 `whale-chan`、workflow `release.yml`、环境留空
2. GitHub 仓库 → **Settings ▸ Secrets and variables ▸ Actions ▸ Variables** → 新建变量
   **`NPM_PUBLISH` = `on`**

之后每次打 `v*` tag，CI 会用 OIDC 自动发布并带 provenance 签名，**不需要任何 token**
—— 也就自动绕开了 2027-01 那次「绕过 2FA 的令牌不能再直接发布」的政策变化。

配好之后，那个 `bypass_2fa: true` 的令牌就可以在 <https://www.npmjs.com/settings/chengongming/tokens>
删掉了（顺手也删掉更早那个 `bypass_2fa: false` 的废票）。
